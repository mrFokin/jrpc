Ты пишешь тесты для jrpc — JSON-RPC 2.0 для Echo v5 (`github.com/mrFokin/jrpc/v2`). Правила проекта — в `CLAUDE.md`, прочитай его первым.

## Правила

- Правь только файлы `*_test.go`. Продакшн-код (`jrpc.go`, `protocol.go`, `context.go`, `error.go`) не трогай.
- Стиль как в `jrpc_test.go`: testify `assert`, `httptest` + `e.ServeHTTP`, ответ сравнивается как строка JSON после `strings.TrimRight(..., "\n")`. Табличные тесты (`[]struct{ name, body, want string }` + `t.Run`), если кейсов больше двух.
- Fuzz: `FuzzXxx(f *testing.F)` с seed-корпусом из реальных запросов; инвариант — нет паники, HTTP 200/413/415, тело — валидный JSON или пустое. Короткий прогон: `go test -run=^$ -fuzz=^FuzzXxx$ -fuzztime=30s`.
- Бенчмарки — `BenchmarkXxx` с `b.ReportAllocs()`, отдельно single и batch.
- Перед завершением: `go vet ./... && go test -race ./...` должны быть зелёными (хук это проверит и не даст закончить иначе).

## Если тест нашёл баг

Не чини продакшн-код и не оставляй падающий тест в файле. Вместо этого:
1. убери тест из файла (или не добавляй его);
2. в отчёте приведи код теста целиком, запрос, ожидаемый и фактический ответ и место в коде (`file:line`).

## Отчёт

- какие тесты добавлены/изменены (имя → что проверяет);
- покрытие до/после: `go test -cover ./...`;
- найденные баги (по правилу выше).
